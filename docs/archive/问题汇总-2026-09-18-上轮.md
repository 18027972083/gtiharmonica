## 二、未解决的核心问题

### P1 — 长音被拆成一串相同的短音（原始问题，**未解决**）

**现象**：曲谱里的长音识别不出来，被拆成很多个等长的短音。

**已确认的根因**（两处布尔 onset 判据联手）：

```python
# transcribe.py:517  只要这一帧是 onset 就断开
if onsets[i] and (i - cur_start) >= min_frames: flush(i); begin(i, p)

# transcribe.py:565  _clean_notes 里合并时，中间有任何 onset 就拒绝合并
blocked = has_onset_between(prev.start + prev.duration, n.start)
```

`onsets` 来自 `dsp.spectral_flux`（**整帧宽带谱通量**）。伴奏鼓点在通量上必然出峰，
于是每个鼓点切一刀；第二把锁又把本该合并的碎片焊死。

实测复现：3 秒长音 + 每 0.25 秒一个鼓点 → **正好 12 个 0.25 秒碎片**。

**我做过的修复**：把判据换成"这个音**自己**停过吗" —— 看该音高的谐波能量
是否塌到典型水平的零头。合成场景下 8/8 通过，长音问题消失。

**为什么这个修复不能用**：

判据要看见"无缝重复音那 46ms 的能量凹陷"，所以辅助分析窗从 2048 缩到了
**1024**。窗长一缩，频率分辨率跟着掉：

- 1024 窗 @22050Hz → 频点宽 **21.5 Hz**
- 低音区 C4 = 261.6 Hz，到 D4 只差 **15.6 Hz**

**一个频点比一个半音还宽** → 判据在低音区根本分不清音级，切分边界整体偏移。

实测代价（同一首歌）：

| | 修复前 | 修复后 |
|---|---|---|
| 音符数 | 545 | **659（+114）** |
| 中位音高 | **C4** | **D4** |
| 平均音高 | 60.80 | 61.05 |

**现状**：判据默认关闭，**长音问题回到原点**。

**正确解法（未做）**：按音高**自适应窗长** —— 低音区用长窗保证频率分辨率，
高音区才用短窗换时间分辨率。等价说法：窗长按"目标频率的周期数"定，而不是
固定样本数。

### P2 — 用户曲目会被重建冲掉（**已缓解，未根治**）

`build.py` 用 PyInstaller 文件夹模式重建时会先整个删掉 `dist\GTIHarmonica`
（日志里的 `INFO: Removing dir ...`），而便携曲库就在那里面。

已有 `rescue_user_songs()` + 构建后恢复，但**它兜不住所有情况**：

`build\songs-backup` 里找回来的。

**当前缓解措施**：
- `build\songs-keep\` —— 独立保险箱，构建不会碰
- 构建日志仍会报"已恢复用户曲目 N 个"

**根治方案（未做）**：把曲库默认位置改到 `%APPDATA%\GTIHarmonica\songs`，
构建产物只读内置曲库。代价是失去"解压即用"的便携性。

### P3 — 我的测试方法论缺陷（导致 P1 没被提前发现）

1. **合成测试的音高选得太窄**：长音测试全用 C5（523 Hz，相邻半音 31 Hz
   > 21.5 Hz 的频点宽），**恰好绕过了低音区的缺陷**。真实歌曲的低音区
   完全没被覆盖。
2. **只断言音符数，没断言音高**：8 个场景检查的是"识别成几个音"，
   没有一条检查"音高对不对"。所以音高坏掉了测试还是全绿。

**改进方向**：
- 长音/切分类测试必须覆盖低音区（C4 以下）
- 必须加音高正确性断言，而不只是计数
- 已经加了 `tools/_cmp_pitch.py`（新旧音高逐音对比），这次就是它抓出的回归

## 四、技术债 / 已知限制

| 编号 | 内容 | 性质 |
|---|---|---|
| D1 | 短窗 1024 在低音区频率分辨率不足（P1 的根因） | 缺陷，待修 |
| D2 | 拍号推断的固有歧义：1.5 与 2.0 是 3:4 关系，3/4 的音符在 4/4 网格上会周期性命中，结构不分明时**本质无法区分** | 物理限制，已把 2/4 移出候选、证据不足时回退 4/4 |
| D3 | 无缝重复音的物理歧义：两个同频**纯正弦**首尾相接，波形完全连续，**它本来就是一个音**，没有可检测的凹陷 | 物理限制，不是 bug |
| D4 | 乐谱层只写不读：`bpm/time_sig/...` 已写进 JSON，但 UI 还没显示、也没参与排版 | 待接入 |
| D5 | `_index_at` 是线性扫描 | 测过不是瓶颈（0.085 ms），保留 |
