## P1 — 长音被拆成一串相同的短音 ✅ 已解决

**你的原话**：「长的音曲谱似乎识别不了，会拆成很多个相同的短音，效果很差」

### 根因（两处布尔 onset 判据联手）

`onsets` 来自 `dsp.spectral_flux`（整帧宽带谱通量）。伴奏鼓点在通量上必然出峰：

```python
# transcribe.py  只要这一帧是 onset 就断开
if onsets[i] and (i - cur_start) >= min_frames: flush(i); begin(i, p)
# _clean_notes 里合并时，中间有任何 onset 就拒绝合并
blocked = has_onset_between(prev.start + prev.duration, n.start)
```

每个鼓点切一刀；第二把锁又把本该合并的碎片焊死。确定性复现：3 秒长音 +
每 0.25 秒一个鼓点 → 正好 12 个 0.25 秒碎片。

### 最终修复（2026-09-18 第二轮）：按音高自适应窗长的重起音判据

判据问的是「这个音**自己**的谐波能量塌过没有」，而不是整帧通量。测量从
「预计算固定 1024 短窗 STFT」改为**时域复解调**：

- 测量窗长 = `REATTACK_CYCLES`(26) 个基频周期，clamp 到 [1024, 8192]：
  C5 ≈ 1095（50ms，与当年验证过的 46ms 行为几乎一致）、C4 ≈ 2189（99ms，
  频率分辨 14.5Hz < 半音 15.6Hz）、G2 ≈ 5850（265ms，5.4Hz）。
  低音区不牺牲频率分辨率、高音区不牺牲时间分辨率 —— 固定窗两头不讨好的
  死结在**每个音高上分别**化解。
- 每谐波 3 个频率点铺 ±3.5% 频带求和（等价旧版「频点求和」），颤音的
  谐波摆动不会被读成塌陷。
- 断裂点距音符起点的保护距离（`safe_from_start`）= 判据观察窗 + 主分析窗
  提前量：voiced 轨迹因主窗白化比真实音起点早若干帧，不补这份距离长音
  开头会被读成 dip=0 误切（实测 0.743s 处切刀的根因）。
- 判据**默认打开**（`reattack_min = 0.28`）。

### 验收数据

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 3s 长音 + 每 0.25s 鼓点（C5） | 12 个碎片 | **1 个音** |
| C4 / C3 长音 + 鼓点 | 12 个碎片 | **1 个音，音高钉住** |
| 颤音长音 / 真重复音 / 无缝重复音 | — | 全部正确（`_check_reattack.py` 10/10） |
| 真实曲谱 round-trip 长音保留 | 青花瓷 1、父亲 9、call of silence 35 | **39、51、52** |
| 转录验收（tests/transcribe_acceptance.py） | 77 项 | **85 项全过** |

真实歌曲（293s MP3）上判据关闭时音符总时长只有 80.4s，开启后 161.5s ——
旧行为把一半以上的有声内容切碎后丢掉了。

### 勘误：当年「音高被抬高」是统计伪影

上一版回退判据的理由是「开启后音符 545→659、按音符个数的中位音高
C4→D4」。本轮插桩证明**那是伪影，不是音高回归**：

- 判据只决定切分、从不产生音高。帧级音高轨迹（Viterbi 输出）在判据
  开关下**完全相同**（同一首 293s 歌：帧级中位 61.5 = D4，两种设置一致）；
- 旧行为把长音切碎后，大量碎片低于 `min_note_ms`(70ms) 被丢弃，留下的
  「按音符个数」分布偏向低音区长音 → 中位数假性偏低（C4）；
- 判据开启后碎音不再误切、丢得少，个数分布回归真实（D4）—— 这正是
  转录更完整的表现，不是音高被抬高；
- 逐音扫描、低音区长音、音阶场景在判据开启下全部通过。

固定 1024 短窗在低音区分不清音级仍是物理事实（15.6Hz 半音 > 21.5Hz 频点），
所以自适应窗长依然是必要设计 —— 但「判据会抬高音高」这个罪名撤销。

### 残余边界（如实交代）

窗长超过 46ms 的音高（约 C4 以下），「无缝重复音」的 46ms 凹陷被稀释到
和鼓点分不开（C4 下 dip 比值 ≈0.94）→ 低音区的无缝重复音可能粘成一个
长音。这是时宽×带宽 ≳ 1 的物理上限；漏判（两音粘住）远比误判（长音
剁碎）轻，且编辑器里手工拆分是现成的兜底，取舍方向正确。

## P2 — 低音区孤立短音被抬高 ⚠️ 未解决

**怎么发现的**：补测试缺口时（原来全用 C5，恰好绕开低音区）+ 新增逐音扫描
才暴露出来。

**实测数据**（逐个音高单独合成，看识别成什么）：

```
36→55(+19)   40→59(+19)   43→62(+19)   45→64(+19)
48→60(+12)   50→62(+12)   52→64(+12)
             G3(55) 往上：全部精确命中 ✅
```

- **G#3（52）往下**：孤立短音被系统性抬高。
- **48–52**：抬一个八度（+12）。
- **45 往下**：被抬到 **3 次谐波**上（+19 = 12 + 7，C2 的第 3 谐波 196 Hz
  正好是 G3）。

**原因**：旋律先验（对数频率高斯，中心 380 Hz）恰好落在音域中点。越低的
基频离中心越远，先验压得越狠；而它的某次谐波反而更接近中心，于是被当成
基频。孤立单音没有上下文，先验直接压过了证据。

**重要缓解**：**连续旋律的低音区是准的** —— 低音音阶（C3 大调，48–60）
实测偏差 **0**。有形上下文时 Viterbi 的转移代价会拉住它。所以这主要影响
孤立的低音短音，真实旋律受影响小得多。

**为什么没顺手改**：改先验中心或权重会影响**所有**已经正常的转录结果。
这属于算法调优，风险独立于 P1（P1 动的是切分判据，P2 动的是音高先验，
两者不相交）。P1 已解决，P2 是下一个候选，但同样要带全量对比来做。

**临时办法**：在编辑器里直接改音高，或者用「调内吸附」。

## P3 — 编辑器里点击不能定位播放头 ✅ 已解决（v0.2.0）

当年顾虑「点击定位和点击选择手势冲突」，最终用了不冲突的方案：

- **底部时间轴条**（卷帘下方 24px 刻度区）整条都是跳转热区 ——
  `ScoreEditor.mousePressEvent` 检测点击落在 `plot.bottom()` 之外就直接
  `seekRequested.emit()`，绘图区里的编辑手势不受任何影响；
- **进度条移进了旋律预览卡片内部**（紧贴卷帘下方，预览/编辑共用），
  之前它在窗口最底部、隔着参数卡，用户根本没认出它是乐谱的进度条；
- `seek` 统一走 `MainWindow._seek_from_roll`：没有试听音频时也移动播放头
  （纯视觉跳转），有音频且对应当前编排时音频即时跳转；**演奏中拒绝跳转**
  并提示先按 F8 暂停；
- 编辑视图的播放头此前**从未被喂过位置**（`_poll_audio` 只喂预览卷帘），
  这是「切到乐谱编辑试听时画面纹丝不动」的根因，已同步修复。

验收：`tools/_check_final_polish.py` 16 项全过。

## P4 — 游戏内实际演奏 ✅ 已确认（2026-09-19）

用户实测：**软件内置曲库的全部 32 首人工精调谱子在游戏内演奏正常**。

### 中途出现并已解决的「按了没反应」事故

一度出现「F8 后进度条在跑但游戏无任何按键」—— 竞品 GTIartist v1.1 反汇编
（`build/jianpu/win_disasm.txt`、`win_full.txt`）证实它的注入实现与我们
逐行一致（SendInput + MapVirtualKeyW 扫描码 + KEYEVENTF_SCANCODE），
唯一差异是**启动即要求管理员权限**：

- 根因是 **UIPI**（用户界面特权隔离）：低完整性进程向提权窗口
  （游戏/WeGame/ACE 均为管理员）发送的输入会被 **静默丢弃**，
  SendInput 还返回成功，没有任何报错线索；
- 修复：`build.py` 的 spec 模板加 `uac_admin=True`（exe 强制提权清单），
  `launcher.py` 加 `_ensure_elevation()` 运行时二次保险（开发态也提权）。

### 残余待确认（不阻塞）
- 游戏接受的最短按键时长（用校准功能测）
- 超长曲目连续演奏的稳定性

## 附：可调参数速查

```python
TranscribeOptions(
    reattack_min = 0.28,     # 「重新起音」判据阈值（默认开启）。
                             # 能量要塌掉 28% 以上才认定是新的重复音；
                             # 0 = 关闭（退回「通量出峰就断开」，长音会碎）。
    reattack_ms  = 60,       # 判据观察窗（毫秒）
    onset_threshold = 0.32,  # 谱通量起音阈值
    min_note_ms  = 70,       # 短于此的音符丢弃
    merge_gap_ms = 45,       # 同音高间隙小于此值就合并
    max_note_ms  = 6000,     # 过长的音符切一刀
)
```

判据的测量窗不再有「固定窗长」可调 —— 它按音高自适应（时域复解调），
模块级常量（`transcribe.py`，改之前先读注释里的物理约束）：

```python
REATTACK_CYCLES      = 26.0   # 测量窗 = 26 个基频周期（频率分辨 ≈1.44/26 ≈ 5.5% < 半音）
REATTACK_MIN_FRAME   = 1024   # 窗长下限（高音区时间分辨率：看得见 46ms 凹陷）
REATTACK_MAX_FRAME   = 8192   # 窗长上限
REATTACK_REL_BW      = 0.035  # 每谐波频带 ±3.5%（盖住颤音摆动）
REATTACK_BAND_POINTS = 3      # 频带内复解调点数
```
