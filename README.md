# 大肥鲸洲琴工具包

《三角洲行动》口琴自动演奏引擎 —— 一套**完全自主实现**的桌面工具。

读取 MIDI / JSON 曲谱，把音符编排成游戏口琴的按键序列，
再通过 Win32 `SendInput` 发送**扫描码**注入游戏自动演奏。

> 本项目的原理来自对闭源程序 `GTIartist v1.1` 的逆向分析，
> 但**全部代码为独立重写**，不包含、也不依赖原程序的任何二进制或授权机制。

---

## 为什么是重写而不是改造

原程序是一个 PyInstaller 打包的闭源软件，带激活码验证，且关键参数写死在代码里：

| | GTIartist v1.1 | 本项目 |
|---|---|---|
| 指法选择 | 固定「修饰键最少」 | 4 种策略可插拔 + DP 全局最优 |
| 参数 | 写死在源码 | 单个 JSON，改完即生效 |
| 校准 | 无 | 测量最小音长 / 注入延迟 / 按键通过率 |
| 试听 | 有 | 有（不干扰游戏） |
| 分析 | 无 | 策略横评、音轨覆盖统计、时序报告 |
| 授权 | 激活码 | 无 |

## 下载直接用（推荐）

不想碰源代码的话，直接到本仓库的 **Releases** 页面下载
`大肥鲸洲琴工具包_vX.Y.Z_便携版.zip`：

1. 解压到任意目录（免安装，不写系统目录，可放 U 盘）；
2. 双击 `大肥鲸洲琴工具包.exe`；
3. 首次打开输入卡密激活，一次即可 —— 验证在本机完成，不联网。

解压后同目录的 `使用说明.txt` 里有完整用法；添加曲谱、找谱技巧见
程序内「齿轮菜单 → 如何添加曲谱 / 使用说明」。

## 从源码运行（开发）

Windows + Python 3.10 以上。不需要管理员权限（除非游戏以管理员运行）。

```bash
pip install PySide6-Essentials        # 图形界面

pip install numpy soundfile           # 音频转曲谱功能所需
                                      # （可选：miniaudio 作为解码兜底）
```

只做演奏、不用音频转曲谱的话，`numpy` / `soundfile` 可以不装——
程序会自动隐藏相关入口，其余功能不受影响。

## 快速开始

```bash
# 1) 先分析，不动游戏：看看这首曲子能不能弹、哪个策略最省力
python -m gtiharmonica analyze song.mid --verbose

# 2) 本机试听，确认旋律和音轨选对了
python -m gtiharmonica preview song.mid

# 3) 校准：测出你的游戏能接受多短的按键
python -m gtiharmonica calibrate --save cal.json

# 4) 正式演奏（3 秒倒计时内切回游戏口琴界面）
python -m gtiharmonica play song.mid --strategy optimal

# 5) 还没有曲谱？把 MIDI 拖进界面（直转 / 旋律化二选一），或用界面里的「导入简谱」
```

演奏中：`F8` 暂停/继续，`F9` 或 `Esc` 停止（会自动松开所有按键）。
倒计时那 3 秒里按 `F9` / `Esc` 可以取消本次演奏。

热键走的是**全局轮询**：游戏在前台时照样收得到，而且不占用按键（不干扰
游戏自己用 F8/F9）。等待期间也以 8 ms 粒度轮询，长音和长间隙里按下就有
反应。切回本程序看进度会**自动暂停**（回游戏按 F8 继续），切到别的程序
会直接停止并释放按键，避免误发。

## 曲库放在哪

**打包版**：`%APPDATA%\GTIHarmonica\songs`
**开发版**：项目根目录的 `songs\`

以前曲库放在 exe 旁边的 `songs\`，而那个位置正好在构建产物 `dist\` 内部，
重新构建会被整个删掉 —— 自己转的谱就这样丢过。现在改到用户数据目录，
构建和重装都不会碰它。想继续便携（U 盘 / 免安装），在 exe 旁边放一个空的
`portable.txt`，曲库就跟着程序走。

首次启动会把旧位置的曲子**自动合并**过来：只补不覆盖、不删原件、可以重复
执行。构建脚本也会在每次构建前后比对曲库清单，**少一首就让构建报错退出**，
而不是写一句「已恢复」然后静默丢文件。

自动合并会**跳过你删过的曲目**：界面里删掉一首（右键 → 从曲库删除）会在曲库
目录里记一笔（`.deleted.txt`），启动补齐与内置示例曲目的安装都不再碰它。没有
这份记录的话，exe 旁边那份曲库里的同名文件每次启动都会把删掉的曲子拷回来
（就是「删除曲目后重启又出现」）。把同名文件重新导入 / 拖回曲库，这条记录
会自动撤销。

曲目**收藏**同样存在曲库目录里（`.favorites.txt`，一行一个文件名）：列表项右边
的星标点一下就是收藏，标题右边的「全部 / 收藏」只看收藏的那几首。两份名单都是
纯文本，跟着曲库目录走，可以手工编辑，也可以跟曲库一起备份。

## 曲谱从哪来（按推荐顺序）

三角洲口琴**只能弹单音轨**，找谱的效果从好到差：

1. **找一份现成 MIDI（推荐）** —— 到 midishow 等站点下载，挑谱三招：
   搜「原琴」（按口琴音域编好，可完美适配）、搜「调教用」（基本都是单轨）、
   用站内的**音轨数筛选**选「1 个音轨」。下载后把 `.mid` 拖进窗口，
   选「单轨提取」（默认项）即入库。
2. **手上的 MIDI 是多轨的** —— 同样选「单轨提取」：程序自动挑出主旋律轨、
   压成单音并规整时值。多轨谱只有收成一条旋律，口琴才弹得出来。
3. **没有 MIDI 才走音频** —— 见下节「音频转曲谱」，它是备选方案。

## 音频转曲谱（内置）

> 定位：**能找现成的单轨 MIDI 就优先用 MIDI**。AI 从录音扒出的旋律，
> 节奏与细节精度比不上人工整理的谱。

> v1.2 曾删掉自研的音频转录（本机质量不稳定）；**v1.10 换成了内置 GAME 的
> ONNX 模型重做**：拖一个音频文件进窗口就能出曲谱，纯 CPU 推理，4 分钟的歌
> 约 30 秒。做法见 `gtiharmonica/audio2score.py`（复现 GAME 的推理流程，
> 不依赖 torch）。
>
> 下面是早先那版自研转录的历史记录，保留供参考。

### 内置版怎么用

顶栏「音频转曲谱」选文件，或直接把 mp3 / wav / flac / ogg / m4a 拖进窗口。
输出单条旋律线（多声部自动压成主旋律），转完进曲库。命令行批量：

```
python -m gtiharmonica transcribe 目录 -o 输出目录     # 打包版 exe 同样支持
```

实测（详见「验证状态」）：同一段人声素材，内置结果与官方 GameInfer.exe
逐音符吻合 94%（±100ms）、音高一致率 92%，且切片失败时不会像官方 CLI 那样
报 `Slice duration exceeds 60 seconds` 退出（有强制切分兜底）。

把下载好的歌（MP3 / WAV / FLAC / OGG）**直接变成游戏里能弹的曲谱**，
不用再去找 MIDI。

### 用界面

顶部工具栏点 **「音频转谱」** → 选文件 → 调参 → 开始转录 → 试听满意后
**加入曲库**。曲谱会出现在列表里，可以立刻演奏。

也可以**直接把音频文件拖进窗口**，会自动打开转录界面并选中该文件；
拖入曲谱文件（MIDI / JSON）则直接进曲库。

### 用命令行

```bash
# 单个文件
python -m gtiharmonica transcribe "song.mp3"

# 整个目录批量转（也会写入曲库）
python -m gtiharmonica transcribe "D:\Music\专辑" --quantize 1/8

# 只预览不保存
python -m gtiharmonica transcribe song.mp3 --dry-run

# 旋律偏低（大提琴 / 男低音）时降低先验权重
python -m gtiharmonica transcribe song.mp3 --prior 0.3

# 三拍子
python -m gtiharmonica transcribe song.mp3 --quantize 1/8t
```

### 处理链

```
音频文件
   ↓  解码（soundfile → miniaudio → ffmpeg 依次兜底）
   ↓  逐帧短时傅里叶变换 + 谱白化
   ↓  对数域加权谐波求和 → 音高显著性面板
   ↓  Viterbi 音高跟踪（连续性 + 八度惩罚）
   ↓  起音检测，切成音符
   ↓  BPM 估计 + 节拍网格量化
   ↓  单声部化（口琴只能单音）
   ↓  音阶吸附 + 八度折叠进口琴音域
可演奏曲谱
```

### 为什么能做得比通用转录简单

通用的「音频转乐谱」是个很难的问题，需要深度学习模型。但这里的
目标不是**通用乐谱**，而是**口琴曲谱**——演奏端只有 8 个按键、
38 个音高，所以只需要提取**单声部主导旋律的音高轮廓**，
不需要复音转录。这让纯 numpy 的 DSP 方案就能达到可用质量，
不必引入 GB 级的模型依赖。

相应地，评测也按口琴的标准来：**音级（音名）正确**才算对，
八度偏移在折叠后落到同一个按键，不计入错误。

### 精度实测

| 场景 | 音级准确率 |
|---|---|
| 8 组合成旋律（音阶/大跳/半音密集/高低音区） | **100%** (70/70) |
| 旋律 + 低音线 + 和弦 + 鼓点（轻/中/重伴奏） | **100%** |
| 真实 MP3（293 秒，545 音符） | 转录耗时 **2.2 秒**（1% 实时） |
| 加性噪声 40 dB | 100% |

### 参数怎么调

界面上的滑块和下拉都对应转录参数：

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `灵敏度` | 0.5 | 漏音多（音符太少）→ 调高；噪音多（碎音太多）→ 调低 |
| `旋律先验` | 0.8 | 低音线被当成了旋律 → 调高；主旋律本身偏低 → 调低 |
| `量化精度` | 1/8 | 节奏对不上 → 换成 `1/4`；节奏细节丢失 → 换成 `1/16` |
| `音阶` | 大调 | 小调曲子选 `minor`；变化音太多选 `penta`；想保留原音高选 `off` |
| `调性` | C | 曲子不是 C 调时改这里，否则整首会走音 |
| `节拍` | 自动 | 自动检测跑偏时手动填（先按 4/4 拍估个数） |

命令行还有两个进阶参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--sensitivity` | 0.5 | 同上 |
| `--prior` | 0.8 | 同上 |
| `--min-note-ms` | 70 | 短于此的音符丢弃；游戏漏读就加大 |
| `--bpm` | 0 | 0 = 自动检测 |

### 质量与限制

- **转录是统计估计，不是精确还原。** 有伴奏、有转调、有人声和音的曲子
  结果会差一些。加入曲库后可以试听，不满意就调参重来。
- **单声部**：口琴只能发一个音，所以和弦会被压成单旋律（保留较高的音）。
- **对纯打击乐 / 无明确旋律的曲子无效**，会提示「识别到的音符很少」。
- **BPM 会自动折算到 72–156**，避免半速/倍速误判（这在音乐上是等价的，
  但节拍网格精度差一倍）。
- **每次转录都独立**，不依赖网络，也不会上传任何音频内容。

## 乐谱编辑器

转录是统计估计，总有切错、认错音的地方。与其反复调参数碰运气，不如直接把
谱子改对 —— 主界面「旋律预览」标题行右侧切到 **乐谱编辑** 即可。

它编辑的不是「按键序列」而是**乐谱本身**：每个音符有音高、起点、时值，
小节线由 BPM 与拍号算出来。改完由 `arrange_from_notes()` 重算指法，所以
「编辑」和「演奏」始终是同一份数据。

| 操作 | 效果 |
|---|---|
| 单击 / Shift+单击 | 选中 / 加选 |
| 拖音符主体 | 改音高与位置 |
| 拖音符两端 | 改时值（拖左端时终点钉死） |
| 空白拖动 | 框选 |
| 双击空白 / 双击音符 | 插入音符 / 在点击处切开 |
| `M` | 合并选中的碎片 |
| Delete | 删除选中 |
| 方向键 | 上下调音高、左右调时间（Shift 一次八度） |
| Ctrl+Z / Ctrl+Shift+Z | 撤销 / 重做 |
| Ctrl+A | 全选 |
| 滚轮 / Ctrl+滚轮 | 左右滚动 / 缩放 |
| 中键拖动 | 平移视图 |

工具行还有：量化（吸到节拍网格）、调内吸附（修 ±1 半音漂移）、清理重叠
（同一音高上时间重叠的音，游戏一次只能按一个键）。信息行会提示「可合并
N 组碎片」，拍号/BPM/调号/调式都能改，改完小节线立刻重排。

**「合并长音」是长音被切碎时最直接的补救**：框选那十几个碎片点一下，
或者什么都不选直接点 —— 会自动合并整首的碎片（导入的曲子里碎片往往散布
全曲，手工框选不现实）。合并按「时间相邻且音高相同」分组，所以不会把
真正分开的音错并到一起。这一步可以撤销，不满意就 Ctrl+Z。

编辑器里的音高**已经是最终要弹的音高**，所以应用编辑时不会再走一遍移调
与八度折叠 —— 否则对已经正确的音高做二次变换就是错音。也因此，编辑模式
下拖动「移调」滑块只重算指法，不会搬走你已经编辑好的音高。

## 核心概念

### 乐器模型

游戏口琴有 8 个音阶键 + 3 个鼠标「修饰键」（**按住**生效）：

```
音阶键  z   x   c   v   b   n   m   ,
音级    1   2   3   4   5   6   7   高音1
MIDI    60  62  64  65  67  69  71  72      (base = 60 时)

修饰键  鼠标左键 = 降一个八度
        鼠标中键 = 升半音
        鼠标右键 = 升一个八度
```

因为修饰键可以组合，同一个音高往往有**多种按法**，例如 MIDI 60 可以是：

```
z                       (不按修饰键)
,  + 鼠标左键            (高音1 降一个八度)
m  + 鼠标左键 + 鼠标中键   (7 降八度再升半音)
```

默认配置下可演奏 **38 个音高，MIDI 48 (C3) ~ 85 (C#6)**。

**选哪个按法**就是本项目最值得优化的地方。

### 处理链

```
MIDI / JSON 曲谱
   ↓  音轨过滤
   ↓  和弦单音化（同时发声的音只留一个，默认取最高音）
   ↓  移调 transpose
   ↓  八度折叠（超音域时 ±12k 折回可演奏范围）
   ↓  指法选择 ★ 策略在这里发挥作用
   ↓  换气 / 连奏 / 速度
演奏计划（每个音：按哪个键、什么时候按、按多久）
   ↓  perf_counter 绝对时钟调度
SendInput 发送扫描码 → 游戏发声
```

### 为什么必须发扫描码

游戏（DirectInput / Raw Input）读取的是硬件**扫描码**。只设置虚拟键码的
`SendInput` / `keybd_event` 通常会被忽略——这是绝大多数自写脚本在游戏里失效的原因。

另外英文标点必须用 OEM 虚拟键码（`ord(',')` 是 44，正确值是 188）。

## 定向优化指南

这是本项目相对原程序最大的价值：**所有影响手感和成功率的量都暴露出来了**。

### 1. 先测量，再调参

不要凭感觉调。先跑校准：

```bash
python -m gtiharmonica calibrate --save cal.json
```

它会测出三件事：

| 测量项 | 用途 |
|---|---|
| 最短可识别音长 | 决定 `min_note`，避免音符被游戏漏读 |
| SendInput 延迟 p95 | 延迟高说明有杀软拦截，需要调 `spin_window` |
| 按键通过率 | 定位哪些键/修饰键没被游戏接收 |

### 2. 挑指法策略

```bash
python -m gtiharmonica analyze song.mid
```

输出示例（宽音域大跳测试曲）：

| 策略 | 按键次数 | 修饰键切换 | 换键次数 | 移动量 | 成本 |
|---|---|---|---|---|---|
| min-modifiers | **42** | 19 | 18 | **87.0** | 76.4 |
| greedy | 46 | 19 | 16 | 51.0 | 70.9 |
| **optimal** | 45 | 19 | **15** | **51.0** | **70.4** |
| stable-key | 46 | 19 | 16 | 51.0 | 70.9 |

怎么选：

- **手上容易按错、修饰键切换老出问题** → 选 `optimal`（切换与移动都最少）
- **游戏漏读按键、希望总按键次数最少** → 选 `min-modifiers`
- **手速吃紧、想少换键** → 选 `stable-key`
- 拿不准就用 `optimal`，它按成本模型给出全局最优解

`analyze` 会顺便验证 DP 的正确性：若某个策略的成本低于 `optimal`，会直接告警。

### 3. 调成本权重

策略「谁更优」由成本模型定义，在配置文件的 `cost` 段：

```json
"cost": {
  "modifier_switch": 1.00,     // 修饰键集合变化 —— 最容易出错，默认最重
  "key_move": 0.35,            // 键盘移动（单位：键宽）
  "extra_press": 0.30,         // 每多按一个修饰键
  "key_repeat_bonus": -0.20,   // 复用同一个音阶键（负值=奖励）
  "octave_jump": 0.15          // 左右键互换的附加惩罚
}
```

调参思路：
- 老是「修饰键没按住/没松开」→ **调大** `modifier_switch`、`octave_jump`
- 手指跨度大够不着 → **调大** `key_move`
- 游戏对多键同按支持差 → **调大** `extra_press`

### 4. 调时间参数

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `speed` | 1.0 | 手跟不上就降到 0.8；0.25–2.0 |
| `gate` | 0.9 | 音符粘连、分不清 → 降到 0.7；太断 → 升到 0.95 |
| `breath_ms` | 90 | 长乐句吹不过来 → 加大到 150；节奏拖沓 → 减到 50 |
| `min_note` | 0.02 | 用校准值；游戏漏读音符就加大 |
| `min_gap` | 0.012 | 相邻同音粘连时加大 |

### 5. 调音高策略

| 参数 | 默认 | 说明 |
|---|---|---|
| `transpose` | 0 | 整曲移调 ±24 半音，用来把曲子挪进音域 |
| `fold_octaves` | true | 超音域折叠；关掉则丢弃超域音符 |
| `fold_prefer` | nearest | `down` 让旋律整体偏低，`up` 偏高 |
| `chord_policy` | highest | 合并音轨时取哪个音；`lowest` 取低音声部 |
| `track` | null | 指定音轨；先用 `tracks` 命令看覆盖率 |

### 6. 调度精度

```json
"scheduler": {
  "spin_window": 0.002,   // 自旋等待窗口，越小越准但越费 CPU
  "poll_interval": 0.02,  // 暂停/热键轮询间隔
  "tight": true           // 音符间无空隙时省略一次 sleep 往返
}
```

时序报告在每次 `play` 结束时打印（平均/p95/最大延迟），用它判断是否需要调 `spin_window`。

## 已知限制

> 完整的当前问题清单（含复现方式与实测数字）见 [`docs/已知问题.md`](docs/已知问题.md)。

- **仅 Windows**：注入依赖 `SendInput`。
- **游戏内键位必须与配置一致**：默认按游戏默认键位。改过键位请同步 `gtiharmonica.json`
  或直接复用原程序的 `instrument.json`（本项目会自动读取）。
- **单音演奏**：口琴一次只能发一个音，多声部会被压成单旋律。
- **建议无边框窗口模式**，演奏期间保持游戏在前台。
- **管理员权限**：若游戏以管理员运行，本工具也需提权，否则 `SendInput` 会被 UIPI 拦截。
- **曲库的删除有"记忆"**：删掉的曲目会记进曲库目录的 `.deleted.txt`，启动补齐
  与内置曲目安装都跳过它（这正是「删除后重启又出现」的修法）。想让某首曲子
  重新受补齐保护，把同名文件再导入一次即可。
- **编辑器里点击不能定位播放头**：点击被用作选择音符。要定位请用卡片下方
  的时间轴滑块。
